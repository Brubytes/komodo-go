# 0.6.0 interactive simulator QA

Date: 2026-09-12. PR: https://github.com/Brubytes/komodo-go/pull/45

Environment: iPhone 17 Pro simulator, iOS 26.5, local Xcode 26.6; debug build from the release branch. Real Komodo Core 2.3.1 at `http://localhost:9121`, backed by the dedicated `komodo_test` Docker Compose project. This was not demo-mode testing. Credentials were entered from the existing local environment and are not included in this report.

## Issues found and fixed

1. iOS smart punctuation changed straight quotes in the compose editor. The actual saved compose file contained curly quotes and Docker Compose rejected it. The app now uses a local adaptation of the syntax_highlight editor with autocorrect, suggestions, smart quotes, and smart dashes disabled. Syntax highlighting, wrapping, line numbers, and indentation shortcuts remain. Controller listeners and scroll controllers are disposed correctly, including after closing fullscreen editing. Re-entering the same configuration through the fixed simulator editor produced literal quotes, passed compose validation, and started nginx.
2. iOS autocorrect changed the resource name `qa-release-060` to `as-release-060`. Create/copy/rename name fields now disable substitutions. Copying a resource as `qa-release-copy` preserved the exact identifier.
3. Empty server/repository/registry selections displayed warnings intended for missing saved values. New stack forms now distinguish empty selections from unresolved existing references; genuine missing values still show warnings.
4. Execute requests were reported as completed successfully even when the backend returned an asynchronous update. Single-action and batch feedback now describe request acceptance. A completed update with `success: false` is treated as an error, including inside native batch responses. The failed compose attempt was readable in update history and execution output.
5. A deployment lasting beyond the one/three-second activity refreshes left the resource showing Deploying. Stack lists now continue refreshing every five seconds while states are Deploying, Restarting, or Removing and refresh related detail/service data. Polling ends once the state settles or the provider is disposed. Activity refreshes also run at 10 and 30 seconds to cover graceful stop/restart and delayed backend caches.
6. Dark-mode primary green was difficult to read against the dashboard/card background. The shared dark accent is brighter; regression checks require at least 4.5:1 contrast for primary text on the theme's surface/card colors and for button labels on primary.

## Interactive coverage

- Added and activated the real local connection; verified Core version and URL in Settings. Saved credentials survived simulator app rebuild/relaunch.
- Dashboard and resource catalog loaded real counts and live server statistics. Enabled the local test server for the session and observed CPU/memory/disk updates; viewed stats intervals and container inventory.
- Created a disposable UI-defined stack, selected its server, edited compose in fullscreen, saved it, and checked backend persistence. The nginx fixture published no host ports and carried the `com.brubytes.qa=release-060` label.
- Reproduced a failed deployment and inspected the actual compose error in update details. Corrected the configuration through the UI, deployed successfully, and verified the running container independently through Docker.
- Opened services and update history; viewed successful and failed updates. Read live nginx logs and searched for `nginx`; filtered output matched the term.
- Stopped and started the disposable stack, observing Stopped and Running states. Opened its container inspection screen and checked its stack ownership link, image, network, command, and restart count.
- Copied and renamed the resource and verified both exact identifiers. Ran batch Stop with only the two QA resources selected and checked its per-resource submitted-update rows. Verified the original container stopped in Docker. Destroyed the original stack containers through the confirmation dialog and deleted both QA resources; the catalog returned to six baseline stacks and no container with the QA label remained.
- Reopened the corrected blank full-form stack creation screen and confirmed the erroneous server warning was gone.
- Inspected light/dark dashboard, resource/detail screens, editor, logs, and update output for clipping, overflow, and legibility.

## Automated verification

The simulator fixes add regression coverage for literal text-input configuration, fullscreen editor lifecycle, blank versus missing selections, completed failures versus pending execution/batch results, long-running deployment refresh, and dark-theme contrast. Final runtime log inspection found no Flutter exceptions or layout overflow reports.

## Limits and release gates

This is an iOS simulator smoke pass, not a real-device upgrade test or exhaustive coverage of every infrastructure operation. It does not verify secure-storage migration from App Store 0.5.4, physical-device background/resume behavior, Android runtime behavior, read-only-user permissions, remote proxy authentication, signed Codemagic artifacts, or store submission readiness. Server system information was unavailable from this local backend despite working live statistics; the app displayed its readable backend error.

The tested fixture used the user's host Docker daemon. Unrelated applications/containers were not modified. See the main release-readiness report for signed RC and device release gates.
